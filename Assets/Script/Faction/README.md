# 진영(야영지) 몬스터 시스템

오픈월드 RPG에서 몬스터를 **한 마리씩 배치하지 않고, "진영" 단위로 배치하고 관리**하는 시스템이다.
레벨 디자이너는 진영 오브젝트 하나만 놓으면 된다. 그 안의 몬스터 생성, 인지, 협동 전투, 복귀, 휴면, 리스폰은 진영이 알아서 처리한다.

---

## 1. 일반 몬스터 배치와 무엇이 다른가

프로젝트에 이미 있는 `SimpleChaser`가 전형적인 "일반 배치" 방식이다. 몬스터가 각자 자기 머리로 판단한다.

| 문제 상황 | 일반 배치 (각자 판단) | 진영 방식 |
|---|---|---|
| 플레이어 발견 | 본 녀석만 달려옴. 옆에서 놀던 동료는 모름 | 한 마리가 보고하면 진영 전체가 반응 |
| 발견 연출 | 시야에 들어오는 순간 즉시 돌진 | 인지도가 차오름: 의심(?) → 조사 → 확인(!) → 전투 |
| 여럿이 덤빔 | 전원이 한 점으로 몰려 겹치고 동시에 때림 → 순간 폭딜 | 공격 슬롯(동시 3마리)만 때리고, 나머지는 주위를 돌며 순번을 기다림 |
| 끌고 다니기 | 몬스터마다 리쉬가 달라서 한 마리씩 끌려나옴 | 영역(리쉬)이 진영 하나라서 무리 전체가 같이 포기하고 같이 복귀 |
| 놓쳤을 때 | 바로 포기하거나 영원히 쫓아옴 | 마지막으로 본 곳에 수색조를 보냄 → 못 찾으면 복귀 |
| 성능 (오픈월드) | 맵의 모든 몬스터가 항상 `Update` | 플레이어가 먼 진영은 통째로 잠듦 (업데이트 0, 오브젝트 비활성) |
| 리스폰 | 몬스터마다 타이머 → 플레이어 눈앞에서 하나씩 생겨남 | 전멸 후 일정 시간이 지나고, 플레이어가 멀리 있을 때 한꺼번에 채워짐 |
| 퀘스트 연동 | "야영지 소탕"을 판단하려면 몬스터를 일일이 추적 | 진영의 `onCleared` 이벤트 하나에 연결 |
| 배치 작업 | 몬스터 12마리를 하나씩 놓고 각자 수치 조정 | 진영 하나 + 경비 자리 / 순찰 경로만 지정 |

핵심 차이는 **판단의 단위**다. 일반 배치에서는 판단 단위가 "몬스터 한 마리"이고, 진영 방식에서는 "집단"이다.
RPG 플레이어는 몬스터를 한 마리씩 상대한다고 느끼지 않는다. "고블린 야영지"라는 하나의 상대를 공략한다고 느낀다.
그래서 게임 코드도 그 단위로 짜는 게 자연스럽다.

## 2. 구조: 3계층

```
FactionManager  (월드에 1개)  누가 어디 있나, 누가 누구 적인가
   └─ FactionCamp  (진영마다 1개)  지금 우리 진영은 어떤 상황인가        ← 진영 FSM
         └─ FactionUnit  (몬스터마다)  나는 지금 무엇을 하고, 어떻게 움직이나 ← 개인 FSM + 보이드
               └─ FactionBody  진영 소속 + 체력 (플레이어에게도 붙음)
```

| 계층 | 책임 | 모르는 것 |
|---|---|---|
| **FactionManager** | 공간 그리드(주변 탐색), 진영 간 적대 판정, 플레이어 거리 | 개별 몬스터의 행동 |
| **FactionCamp** | 경보 공유, 진영 상태 결정, 공격 슬롯 관리, 조사조 지정, 휴면/리스폰 | 몬스터가 어떻게 걷는지 |
| **FactionUnit** | 자기 눈으로 보기(인지도), 진영 명령 수행, 보이드 이동 | 진영 전체 상황 판단 |

몬스터는 **보고만 하고 결정은 진영이 한다.** 그래서 "한 마리는 싸우고 옆 녀석은 놀고 있는" 어색한 장면이 구조적으로 생기지 않는다.

## 3. 왜 FSM이 두 단계인가

### 진영 FSM (`FactionCamp`)

```
Dormant ─(플레이어 접근)─▶ Calm ─(의심)─▶ Alert ─(확인)─▶ Combat
   ▲                        ▲ ◀─(조사 끝)──┘ ◀─(놓침: 수색)──┘ │
   └─(플레이어 멀어짐)──────┘ ◀─(영역 밖 도주 / 적 사망)───────┘
Cleared ─(리스폰 시간 + 플레이어 멀리)─▶ Calm / Dormant
```

### 개인 FSM (`FactionUnit`)

```
Idle ⇄ Investigate
  │        │
  ▼        ▼
Engage ⇄ Attack     (진영이 Combat이면)
  │
  ▼
Return → Idle       (진영이 Calm으로 돌아오면)
(어느 상태든) → Dead
```

상태가 한 단계뿐이면 "진영이 경계 중인데, 나는 조사조로 뽑혔고, 지금 조사 지점에 도착해서 두리번거리는 중" 같은 상황을 enum 하나에 다 담아야 한다.
그러면 `AlertAndInvestigatingAndArrived` 같은 상태가 폭발적으로 늘어난다.
두 단계로 나누면 각 FSM이 작게 유지된다.

- 진영 FSM은 **상황**(평온 / 경계 / 전투)을 다룬다.
- 개인 FSM은 **행동**(배회 / 조사 / 접근 / 공격 / 복귀)을 다룬다.
- 둘을 잇는 지점은 진영 → 몬스터 명령 몇 개(`OnCampCombat`, `OnCampCalm`, `BeginInvestigate`, `StandDown`, `ResetToPost`)와 몬스터 → 진영 보고 두 개(`ReportSuspicion`, `ReportSighting`)뿐이다.

개인 상태는 `Enter / Tick / Exit`를 가진 **클래스**로 만들었다 (`FactionUnit.States.cs`).
`Attack.Exit`에서 공격 슬롯을 반납하는 것처럼 "나갈 때 꼭 해야 하는 정리"를 한곳에 둘 수 있다.
상태를 추가할 때도 클래스 하나만 늘리면 된다.

## 4. 왜 보이드로 움직이는가

FSM은 **무엇을** 할지 정하고, 보이드는 **어떻게** 움직일지 정한다.
모든 상태가 같은 재료(분리 / 정렬 / 응집 + 목표 힘)를 비율만 바꿔 섞는다.

| 상태 | 섞는 힘 | 결과 |
|---|---|---|
| Idle (배회조) | 분리 + 정렬 + 응집 + 진영 끈 + 배회 | 무리 지어 어슬렁거림 |
| Idle (순찰) | 분리 + 정렬 + 응집 + 순찰 지점 | 대열을 이뤄 함께 이동 |
| Engage (추격) | 강한 분리 + 약한 정렬 + 목표 | 뭉쳐서 달려오되 겹치지 않음 |
| Engage (대기) | 넓은 분리 + 거리 유지 + 서성임 | 공격자 바깥에 원을 그리며 기회를 엿봄 |
| Attack | 넓은 분리 + 거리 유지 (응집 끔) | 표적 주위에 **원형 포위가 저절로** 생김 |

자리를 미리 계산해서 "너는 3시 방향, 너는 6시 방향" 하고 배정하지 않아도 된다. 힘의 균형만으로 포위와 대기열이 생긴다.
몬스터가 죽거나 새로 끼어들어도 남은 녀석들이 자연스럽게 빈자리를 메운다.
`SimpleChaser`처럼 전원이 한 점으로 겹치는 문제가 없다.

## 5. 핵심 장치

### 공격 슬롯 (공격 토큰)
- 표적 하나에 동시에 붙어서 때릴 수 있는 수가 `maxAttackersPerTarget`(기본 3)으로 정해져 있다.
- 슬롯을 얻은 몬스터는 `attacksPerTurn`번 때리고 양보한 뒤, `slotCooldown`만큼 물러난다. 그래서 공격하는 몬스터가 계속 바뀐다.
- 플레이어 입장에서는 "12마리에 둘러싸였지만 감당할 수 있는" 전투가 된다. 다대일 RPG 전투에서 거의 표준으로 쓰는 기법이다.

### 인지도 (`Awareness`, 0~1)
- 시야에 적이 들어오면 인지도가 차오른다. 가까울수록 빠르다.
- `suspicionLevel`(0.35)을 넘으면 진영이 경계 상태가 되고, 가까운 2마리가 조사하러 간다.
- 1에 도달하면 진영 전체가 전투에 들어간다.
- 등 뒤로 몰래 지나가기, 멀리서 들킬락 말락 하기 같은 플레이가 가능해진다. 머리 위 ?/! UI는 `Awareness` 값을 읽어서 붙이면 된다.
- 맞으면 인지 단계를 건너뛰고 바로 전투에 들어간다.

### 영역과 복귀
- 적이 `leashRadius` 밖으로 나가면 진영 전체가 추격을 포기한다.
- 복귀하는 동안에는 적을 무시하고 체력을 빠르게 회복한다. RPG의 "리쉬 리셋"이다.
- 시야에서 놓친 경우에는 바로 포기하지 않고, 마지막으로 본 위치를 수색한다.

### 오픈월드 휴면과 리스폰
- 플레이어가 `sleepDistance` 밖에 있고 진영이 평온하면, 진영 전체가 잠든다. 업데이트를 하지 않고, 오브젝트도 비활성화한다.
- 깨어날 때는 항상 제자리, 풀피 상태다.
- `wakeDistance`(60)와 `sleepDistance`(80)를 다르게 둔 것은 경계선에서 자고 깨기를 반복하지 않게 하기 위해서다.
- 전멸하면 `respawnTime`이 지나고, 플레이어가 `respawnMinDistance` 밖에 있을 때만 다시 채워진다.

## 6. 씬 세팅

1. 빈 오브젝트에 **FactionManager**를 붙인다. 플레이어는 `Player` 태그로 자동으로 찾는다.
2. 플레이어에 **FactionBody**를 붙이고 `faction = Player`로 설정한다. 이래야 몬스터가 플레이어를 적으로 인식한다.
3. 몬스터 프리팹에 **FactionUnit**을 붙인다. FactionBody는 자동으로 추가된다.
   - `groundMask`: 지면 레이어만
   - `sightBlockMask`: 벽, 바위
   - `obstacleMask`: 피해 갈 장애물
4. 진영 위치에 빈 오브젝트를 만들고 **FactionCamp**를 붙인다.
   - `spawns`: 프리팹 / 수 / 역할. 예) 경비 4, 배회조 6
   - `guardPosts`: 빈 오브젝트 몇 개. 위치와 바라보는 방향(파란 축)이 경비의 자리와 시선이 된다.
   - `patrolRoute`: 순찰 지점들 (선택). 비워두면 배회조는 진영 안에서 어슬렁거린다.
5. 씬 뷰 기즈모로 상태를 확인할 수 있다.
   - 진영 원 색: 초록 = 평온, 노랑 = 경계, 빨강 = 전투, 회색 = 휴면
   - 몬스터 머리 위 색: 초록 = Idle, 노랑 = Investigate, 주황 = Engage, 빨강 = Attack, 회색 = Return
   - 인지도 막대: 흰색은 의심 전, 노랑은 의심

> 플레이어가 몬스터를 때리려면 공격 판정 시점에 앞쪽 `FactionBody`를 찾아서 `TakeDamage(데미지, 플레이어의 FactionBody)`를 호출하면 된다.
> 현재 `PlayerAttack`은 애니메이션만 재생한다.

## 7. 한계와 확장 방향

- **길찾기 없음**: 보이드는 국소적인 회피만 한다. 벽 너머나 미로 같은 지형에서는 막힌다.
  지형이 복잡하면 Return / Investigate / 원거리 추격에만 NavMesh 경로의 다음 코너를 목표점으로 쓰고, 근거리 움직임은 지금처럼 보이드로 처리하는 방식을 추천한다.
- **역할 확장**: `Role`에 원거리(Archer: 거리 유지 + 슬롯 불필요)나 대장(Leader: 죽으면 진영 사기 저하 → 도주)을 추가하기 좋다.
  진영에 `OnMemberDied` 훅을 하나 두면 된다.
- **진영 간 전투**: `FactionManager.rivalries`에 고블린-오크처럼 쌍을 넣으면 몬스터 진영끼리 싸운다. 기본값은 몬스터끼리 서로 무시한다.
- **세이브**: 진영 단위로 `State`, 리스폰 남은 시간, 생존 수만 저장하면 된다. 몬스터 개개인을 저장할 필요가 없다.
